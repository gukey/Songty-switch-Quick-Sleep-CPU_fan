# 后台工具中心模块说明

## 一、统一宿主

对外交付 `DisplaySwitcher.exe` 与使用说明。EXE 内嵌所需运行时、温控助手、迅雷后台和完整 MultiMonitorTool 文件。第一次启动将组件释放到用户应用数据目录，按压缩包内容哈希分目录保存，后续启动校验并复用。

所有模块共用一个系统托盘图标。内部可以有多个工作进程，它们由主程序启动和停止，各自不再创建托盘。启动和 F3/F4 切屏保持静默。单击托盘图标打开主界面，点击关闭按钮收回托盘。右键选择「退出」关闭所有模块。每次从新位置启动 EXE，按实际路径登记当前用户自启动项，替代已整合程序的旧启动入口。

## 二、模块作用与实际效果

| 模块 | 作用 | 使用效果 |
| --- | --- | --- |
| 显示器切换 | 识别物理电视身份，记录 Windows 当前办公排列，验证路径后切换拓扑 | F3 仅电视活动，F4 恢复最近办公扩展布局；应用窗口归集到目标主屏 |
| 窗口迁移 | 处理普通、最大化、最小化应用窗口，复查切屏后出现的窗口 | 返回办公时应用内容集中到 Windows 当前主屏，最小化窗口重开也应回到该屏 |
| CPU/GPU 温控 | Python 温控助手读取硬件传感器，按原串口协议通知 ESP32 | 主界面与托盘显示实时波形，界面显示端口和连接状态 |
| 快速关屏 | 右 Alt 单独松开后暂停媒体，再请求关闭显示器电源 | 无需打开主界面操作，F3/F4 仍独立负责桌面输出切换 |
| Caps Lock 提示 | 共用宿主键盘钩子，用 WPF 绘制大小写状态浮层 | 仅提示大小写，约 1.15 秒后真正隐藏，不抢焦点、不占任务栏或额外托盘 |
| 迅雷磁力导入 | 保留 Python 队列、去重、规则、历史记录与中文本地网页 | 后台持续处理合格磁力任务，手动打开网页查看状态和历史 |
| 自启动 | 读取当前进程 EXE 路径，登记并核对当前用户启动项 | 移动 EXE 后退出旧实例，再从新位置运行一次即可更新路径 |

显示器切换尽量保留已有显示模式，恢复实际结果会被再次查询。设备缺失、路径验证失败或窗口无法归位会记录到日志和主界面状态。系统权限或应用自身窗口行为可能影响归位，程序不会只凭外部命令退出就认定成功。

## 三、大小写提示与切屏残留

默认仅监测 Caps Lock。Num Lock 和 Scroll Lock 不显示提示。浮层在当前主屏底部显示，使用工具窗口、不激活、鼠标穿透等样式。定时结束后调用原生窗口隐藏，而非只将内容变透明。

F3/F4 切换开始、显示设备变更或休眠相关事件发生时主动收起浮层。浮层被排除在宿主的普通应用窗口迁移逻辑之外。下一次按 Caps Lock 时重新取得主屏工作区域并计算位置。

设计参考 [keyboard-lock-osd](https://github.com/gukey/keyboard-lock-osd)。整合版使用新的 WPF 实现，不启动独立 Tauri 程序。旧 OSD 应退出，避免两种提示同时出现。

## 四、迅雷监听与队列

主界面提供「开始监听 / 暂停监听」切换按钮，托盘右键提供两个对应入口。监听状态持久化到本机配置。通过网页切换监听时，后台也会向宿主报告实际状态。

| 操作 | 新链接采集 | 已入队任务 | 其他模块 |
| --- | --- | --- | --- |
| 开始监听 | 从新的剪贴板变化中采集磁力链接 | 按队列设置继续 | 持续运行 |
| 暂停监听 | 停止读取剪贴板 | 继续处理 | 持续运行 |
| 网页「暂停队列」 | 取决于监听开关，可继续采集 | 暂停领取下一条任务 | 持续运行 |
| 退出主程序 | 停止 | 请求有序停止 | 一起退出 |

暂停监听后可以使用本机迅雷客户端复制下载链接。恢复时第一次读取只记录当前剪贴板内容，跳过暂停期间遗留的链接。下一次新复制的磁力链接才进入队列。程序启动时同样先建立剪贴板基线，监听关闭状态会在重启后保留。

已经提交到迅雷的远端下载任务由迅雷执行。暂停本工具的监听或队列，不会取消远端下载。队列暂停也不会撤回正在提交中的请求。

## 五、迅雷规则与控制中心

后台先解析完整文件清单，过滤样片、预告及不满足大小下限的视频，只提交最大合格主视频。默认严格大于 200MB，下限可在网页修改。文件大小未知、清单不完整或解析失败时不进行整包下载。

任务、去重记录、筛选详情和提交结果存入 SQLite。网络中断而提交结果不明时标为「待核对」，需要核实后再决定重试。成功提交通过统一托盘显示通知，表示迅雷接受创建任务，下载完成情况仍以迅雷为准。

本地网页默认地址为 `http://127.0.0.1:8787/`。只有手动选择「迅雷控制中心」才打开浏览器。网页提供批量输入、文本导入、队列暂停、监听开关、搜索分页、失败重试、规则编辑和 CSV 导出。主界面关闭后这些后台功能继续运行。端口被旧控制台占用时，新服务会报告未就绪，并在启动队列前停止，避免重复处理。

## 六、数据位置与迁移

统一数据根目录为 `%LOCALAPPDATA%\DisplaySwitcher`。

| 子路径 | 内容 |
| --- | --- |
| `settings.json` | 目标电视物理身份、F3 快捷键 |
| `office.json` / `office.cfg` | 办公显示拓扑与工具快照 |
| `gaming.json` / `gaming.cfg` | 电视显示拓扑与工具快照 |
| `components/<内容哈希>/` | 已校验的内置组件缓存 |
| `logs/` | 宿主、显示切换与工作进程诊断 |
| `xunlei/settings.json` | 迅雷接口、本地端口、凭据、监听状态 |
| `xunlei/rules.json` | 主视频筛选规则 |
| `xunlei/data/tasks.db` | 队列、历史、去重和文件详情 |
| `xunlei/migration-backup/tasks.db` | 旧程序的迁移前数据库备份 |
| `xunlei/logs/` | 迅雷业务日志 |

源码提供 `XunleiWorker/migrate.py`。先退出旧实例，再执行迁移。工具拒绝覆盖已有目标数据，通过 SQLite backup 接口只读导出原库，保留原配置中的接口与筛选规则，将旧的未完成任务标为「待核对」，避免升级后自动重新提交。原数据库不被修改。凭据、数据库、日志和本机配置只保存在本机，不提交源码仓库。

## 七、进程生命周期

### 高负载与采集故障保护

温控串口进程与硬件采集子进程分开。硬件采集崩溃或连续 30 秒无新样本时，只替换采集子进程，串口维护循环继续运行。样本超过 12 秒视为过期。采集进程使用普通优先级，负责串口的后台进程请求较高一级优先级。

NVIDIA GPU 温度通过有超时限制的 `nvidia-smi` 子进程读取，避免 OpenHardwareMonitor 的 NVIDIA 功耗读取路径。循环变慢不会被当成系统唤醒，也不会据此断开正常串口。主界面采用软件渲染，托盘在任务栏重建、显示事件和周期维护时重新注册。

缺少有效 CPU 或 GPU 温度时，对应串口通道发送 **120°C 保护值**。这不是实测温度，主界面仍显示缺失状态和保护说明。按提供的 ESP32 固件规则，达到 80°C 会请求 100% 占空比。此措施依赖串口可用及设备实际刷入相同控制规则，不能替代设备端的独立失联保护。现有固件在双通道超过 12 秒无有效数据时会停扇，PC 断电、蓝牙彻底断开等情况仍需设备端另行处理。

宿主通过标准输入向迅雷后台发送开始、暂停和退出命令，通过标准输出接收就绪状态和通知。退出时先请求后台停止，再等待工作线程和本地服务退出，超过时限才清理进程树。宿主意外退出导致输入管道关闭时，迅雷后台也会请求停止。

温控助手、显示器操作、Caps Lock 提示和迅雷监听彼此独立。暂停迅雷监听不会停用键盘钩子、全局热键或 ESP32 温控。

## 八、源码入口与验证

| 文件 | 职责 |
| --- | --- |
| `DisplaySwitcher/MainWindow.xaml.cs` | 宿主、状态展示和统一生命周期 |
| `DisplaySwitcher/Services.cs` | 托盘、自启动、键盘钩子和温控进程 |
| `DisplaySwitcher/DisplayBackend.cs` | 电视与办公切换流程、验证和异常恢复 |

| `DisplaySwitcher/CapsOverlay.cs` | 大小写提示绘制、定位与真实隐藏 |
| `DisplaySwitcher/XunleiService.cs` | 迅雷工作进程和宿主通信 |
| `XunleiWorker/host.py` | 无独立托盘和自启动的迅雷后台入口 |
| `XunleiWorker/app/worker.py` | 剪贴板采集和任务处理循环 |
| `XunleiWorker/app/selection.py` | 主视频选择规则 |
| `XunleiWorker/app/database.py` | SQLite 历史、队列、去重和迁移 |
| `XunleiWorker/app/dashboard.py` | 本机网页和管理 API |
| `build.ps1` | 构建后台并内嵌到单个 EXE |

业务代码源自用户项目 XunleiAutoImport。测试使用临时目录和模拟接口，覆盖筛选、去重、结果不明、暂停监听、恢复基线及持久化。测试不会向真实迅雷提交下载任务。

```powershell
cd XunleiWorker
python -m unittest discover -s tests -v
```

构建前将 `XunleiWorker/requirements.txt` 安装到打包 Python 环境，再从根目录执行 `build.ps1`。所需组件会在构建时内嵌，发布仍为单 EXE。
